# Multilingual post-hoc scan

EXNIHILO's generator is language-blind. Language knowledge belongs only in downstream analysis.

## Principle

A generated byte stream may be decoded or mapped into a specified writing system for analysis, but the generator must never use that language's vocabulary, corpus, grammar, tokenizer, or model.

## Important limitation

A raw byte stream does not inherently contain "English", "Ancient Greek", Hindi, or any other language. A detector must define an encoding/character representation before it can search for words.

Therefore every multilingual result must record:

- detector language
- character encoding / normalization
- dictionary or corpus version
- minimum match length
- exact byte/character offset
- generated dataset hash
- detector version

## Suggested detector families

- English
- Ancient Greek
- Latin
- Sanskrit
- Hindi
- Marathi
- Japanese
- Arabic
- Russian
- Chinese

Short matches are expected in sufficiently large random datasets. The interesting statistic is the distribution of match lengths and multi-token sequences under the exact null model, not the existence of a single short word.

## Ancient languages

Ancient Greek is especially interesting because its Unicode representation and historical spelling conventions must be specified carefully. A detector should not silently normalize away distinctions and then count a match as stronger evidence than it actually is.
